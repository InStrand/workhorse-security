## What is verified

- `test/run.sh` on macOS: 47 Node tests, 10 canaries, the pre-push gate test, shellcheck. Linux runs in CI from the first public push.
- An independent architecture pass (bead `whs-m6y.3.17`) closed the six gaps the first review listed and four defects it had not: an encoded slash in a file name matched an exception, a scanner ignore file with a real fingerprint hid findings, git attributes could hide files from two scanners, and a report with no results read as clean. Each has a planted negative in `test/`.
- `whs audit prepare` prepared eight audit runs of real repositories. The audits ran under coordinator sessions that followed the skill. Seven quick-profile runs used 93 of the 134 agent runs their ceilings allowed. Their records belong to the repositories' owner and are not here.

## What the first audits showed about the pack

- A ceiling per run works when reconnaissance comes first: the coverage ledger gives the number of units, and the cost follows from it. `whs` does not compute this yet.
- With no sandbox on the operator machine, no target code is executed. Most records then end as `needs_validation`, each with the check that settles it. Many of those checks repeat across records (identity provider settings, deploy contexts, branch rules), so the report should group records by the fact to check.
- The repository config can keep a folder out of the model's copy, but cannot let named files back in. Keeping a whole documentation folder out also hides the design documents an audit would use.
- A coordinator can be stopped for hours by one approval prompt in a subagent. An unattended run needs a watcher.
- The model that runs an audit is a cost decision the operator must make before the run. The first reconnaissance ran on a more expensive model than the owner wanted.
